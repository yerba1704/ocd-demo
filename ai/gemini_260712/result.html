API Package

The API package contains all information to interact with ora* CODECOP. It is executable by all users and works with invokers rights.

Summary of API Exceptions

Exception Description
E_RULE_FAILED The rule failed because the specified SQL returned more than 0 rows.
E_INVALID_RULE_ID The given ID for the rule could not be found.
E_INVALID_CODE The given CODE for the rule could not be found.
E_INVALID_VALUE The given VALUE for the rule_object, severity, characteristic or tag could not be found.

VERIFICATION_RESULT FunctionFUNCTION

Execute the sql statement from RULE_ID or CODE in RULESET.

Syntax

function verification_result(
    i_rule_id_or_code in varchar2);

Parameters

Parameter Description
i_rule_id_or_code A valid RULE_ID or CODE from RULESET. If not valid exception E_INVALID_RULE_ID or E_INVALID_CODE is raised.

Examples

select * from occ.api.verification_result(i_rule_id_or_code => 'PARAMETER_NAMING_RULE');

CHECK_RULES ProcedurePROCEDURE

Verify all rules that belongs to one of the associated dimension (rule_object, characteristic, severity), a tag or to all defined rules.

Syntax

procedure check_rules(
    i_value         in varchar2 default null,
    i_verbose_mode  in boolean default true,
    i_raise_if_fail in boolean default false);

Parameters

Parameter Description
i_value One of the following rule_objects, severities, characteristics: PLSQL_UNIT, SQL_DATA_OBJECT, DATABASE_OBJECT, APEX INFO, MINOR, MAJOR, CRITICAL, BLOCKER CHANGEABILITY, EFFICIENCY, MAINTAINABILITY, PORTABILITY, RELIABILITY, REUSABILITY, SECURITY, TESTABILITY or one of the defined TAGS (case insensitive). If a severity keyword is chosen, all severity levels greater or equal are used. If parameter is not valid exception e_invalid_value is raised. If parameter is NULL all available rules will verified.
i_verbose_mode Adjust the amount of details.
i_raise_if_fail Raise an exception if a rule is failed.

Examples

exec occ.api.check_rules(i_value => OCC.API.MAINTAINABILITY);
